## 阶段 0：代码加固 + 工程化

| 维度 | MVP 现状 | 生产做法 | 差距/优化路径 |
|---|---|---|---|
| 类型安全 | 手写 `types.ts` 全类型、无 any | schema 驱动（zod）校验运行时数据 + 类型推导 | 工具入参可加 zod 校验 |
| 异常兜底 | 全局 try/catch + 固定 3s 重试一次 | 指数退避重试、超时控制、熔断降级、错误分类（可重试/致命） | 重试改退避策略；按状态码分类 |
| Token 统计 | 追加写 `logs/token-usage.log` | 结构化指标（Prometheus/Influx）+ 监控看板 + 成本告警 | 对接指标系统（Todo5-4 批量评测） |
| 配置管理 | `.env` + 启动校验（缺 key 即退出） | 配置中心/密钥管理（Vault/SSM）+ 多环境（dev/stage/prod） | 密钥轮换曾暴露的 key 优先 |
| 日志 | console 分级（INFO/WARN/ERROR + tag） | 结构化 JSON（pino/winston）+ ELK/Loki 采集检索 | 日志改 JSON 格式 + 采集 |
| 可观测性 | 仅日志，无链路追踪 | OpenTelemetry 全链路 trace（每个工具调用 span） | 阶段 4 Web 服务时补 |
| CI/CD | 无 | GitHub Actions：typecheck + lint + eval 回归 + 构建发布 | Todo5-5 |
| 坑 | 密钥曾明文出现在 agent.ts（已移 .env） | 密钥任何情况不入库/不落盘 | 已轮换提示（未实际轮换） |

## 阶段 1：上下文管理 + 长期记忆

### 1. 上下文窗口管理

| 维度 | MVP 现状 | 生产做法 | 差距/优化路径 |
|---|---|---|---|
| token 估算 | 启发式 `字符数/2 + 4`（中文偏差约 2 倍） | tiktoken / tokenizer 精确计数 | 换真实 tokenizer，估算驱动压缩阈值 |
| 压缩时机 | 每轮发送前检查，超 `MAX_CONTEXT_TOKENS` 即摘要 | 按模型上下文上限的 80% 水位提前压缩；滑动窗口 + 摘要分层 | 引入"水位-压缩"两级策略 |
| 摘要方式 | LLM 一次压缩 head 为一段 system 摘要 | 分层摘要（近窗口保留原文，远窗口递归摘要），结构化记忆（facts 列表） | 增加记忆分层/递归压缩 |
| 失败降级 | 摘要失败→占位 system 消息（等同截断） | 降级到 BM25/向量检索补回关键事实 | 已具备降级思路，可接检索兜底 |
| 坑 | 短会话单条超长消息永不压缩（head 保护逻辑绕过）；tool_calls 配对不能拆散 | 协议完整性是硬约束，生产同样处理 | 已正确实现 |

### 2. 长期记忆（pgvector）

| 维度 | MVP 现状 | 生产做法 | 差距/优化路径 |
|---|---|---|---|
| 存储 | 单表 `memories`（content + vector） | 记忆分层：episodic / semantic / procedural，按重要性分级保留 | 设计记忆分级与遗忘策略（如最近最少使用淘汰） |
| 写入 | 模型自主调 `save_memory` + 精确去重（同内容） | 后台 memory extraction（每轮自动提炼），语义去重（向量相似度合并） | 增加自动提炼管道；语义去重（目前仅精确匹配） |
| 检索 | `retrieveRelevantMemory` Top-3 + 阈值 0.55，余弦距离 | 混合检索（关键词+向量）+ 时间衰减（近期记忆加权） | 增加时间衰减、召回多样性 |
| 注入 | 每轮强制注入临时 system 前缀（不落历史） | 上下文组装器（memory + instruction + 会话 按预算分配） | 已具雏形，可做预算分配 |
| 坑 | nomic 短查询排序不稳（猫查询 Top1 偏差）；注入记忆诱导模型重复 save（改写副本） | 换强 embedding 或 rerank；注入文案加"勿重复保存"约束 | 两个坑都已记录并有解法 |

## 阶段 2：RAG 知识库

| 维度 | MVP 现状 | 生产做法 | 差距/优化路径 |
|---|---|---|---|
| 文档加载 | 启动时 `ingestDirectory` 全量重灌，支持 .md/.txt | 增量更新管道、文档版本管理、失败重试队列 | 改增量：hash 比对 + 只更新变更分块 |
| 分块 | 固定 300 字窗口 + 50 重叠 | 标题/语义感知分块，表格代码特殊处理，按模型调优 | 增加 markdown 结构感知切块 |
| 向量化 | 本地 nomic-embed（768 维，Matryoshka 截断踩坑） | bge-m3 / text-embedding-3，中文场景效果明显更好 | 换模型 + 维度调优（A/B 评测验证） |
| 检索 | 纯向量余弦 Top-K（无阈值） | 混合检索（BM25 + 向量融合）+ reranker + 动态阈值 | 增加 BM25 与 rerank，按评测数据定阈值 |
| 元数据 | 仅 doc_id/doc_name | 权限/部门/时间过滤，多租户隔离 | 表加权限字段 + WHERE 过滤 |
| 工具化 | `search_knowledge_base` 模型自主调用 | query 路由（先判"该不该查库"）+ 强制候选项注入 | 解决"模型过度自信不调工具"（评测 5/7 的根因） |
| 溯源 | 裸回答 | 回答必须带引用（文档/章节/分块索引） | 检索结果带 chunk 定位，回填引用 |
| 防幻觉 | 无护栏 | 答案与检索片段一致性校验，不一致重试/拒答 | 可加一致性校验器 |
| 评测 | `scripts/eval-rag.ts` 7 用例关键词判题 | 评测集 + 回归 CI + LLM-as-judge 判分 | 扩大用例集，接入 CI（Todo5-4/5-5） |
| 坑 | ① 模型"以为知道就不查"（核心功能题编造通用答案）② 固定切块把章节句尾/句首拼进同一块 | 对应生产"query 路由"与"语义分块" | 两坑已量化（回答准确率 5/7 的原因） |

## 阶段 3：任务规划 + 多 Agent 编排

| 维度 | MVP 现状 | 生产做法 | 差距/优化路径 |
|---|---|---|---|
| 规划 | 一次性拆解（planTask），任务转写可能引入幻觉参数（"15项功能"） | 拆解前校验参数与原文一致性；拆解后人工/规则确认再执行 | run_task 参数原文透传或要素校验 |
| 编排 | 手写 while 状态机 + LangGraph 双实现；串行波次执行 | 并行波次（Promise.all）、动态重规划（执行中发现计划不对可回 Planner） | 就绪集合并发执行；re-plan 环 |
| 执行 | run_task 同步阻塞整轮对话（实测 4 分钟） | 异步任务队列 + 进度事件流（SSE/WebSocket），断点续跑 | 阶段 4 Web 化时接；LangGraph checkpoint 是现成路径 |
| 校验 | Reviewer 单模型判断；digest 头尾保留防截断假阴性；失败降级放行 | 校验器与被审者异构模型交叉；要素级 checklist 判分；降级放行需带人工复核标记 | verdict 附证据引用；failed 态触发人审 |
| 记忆协同 | Executor 白名单禁 save_memory（防幻觉入库，实测已毒化过一次） | 记忆写入带来源与置信度分级，幻觉可标记/回收 | 记忆审核管道 + 淘汰策略 |
| 资源 | 子会话跑完即 clearSession 回收（3-7 修复） | 会话池 + TTL；多实例下状态外置 Redis/PG | 阶段 4 落库 |
| 坑 | ① 任务转写幻觉（外层模型改写参数）② Reviewer 约束解码空转（finish=length 空输出）③ 幻觉记忆污染下游（id=20/21 已删）④ redoIds 消费时机 bug（LangGraph reducer merge 让旧产出复活） | — | 全部已记录并修复/缓解 |

**手写 vs LangGraph 实测结论**：≤4 节点固定流程手写更透明（重试环 20 行 vs 框架 3 处配合）；要 checkpoint/流式/人审中断时框架收益反超。详见 README「多 Agent 编排」章节。

## 阶段 4：Web 服务 + 前端控制台

| 维度 | MVP 现状 | 生产做法 | 差距/优化路径 |
|---|---|---|---|
| 会话存储 | 进程内存 Map，重启即丢 | PG/Redis 持久化 sessions/messages，多实例共享 | 阶段 5 或迭代：会话落库 + TTL |
| 对话传输 | SSE 流式（手写 fetch 解析） | SSE/WebSocket；断线重连 + 事件序号续传 | 加 Last-Event-ID 重放 |
| 长任务 | run_task 同步阻塞整轮 HTTP（实测 4 分钟） | 异步任务队列 + 进度事件 + 断点续跑 | LangGraph checkpoint 是现成路径 |
| 鉴权 | 无（任何人可访问） | JWT/API Key + 会话归属校验 + 限流 | 上线前必须补 |
| 监控 | 内存计数（耗时/成功率），进程重启清零 | Prometheus 指标 + 告警 + 链路追踪 | metrics.ts 换 prom-client |
| 部署 | Docker 多阶段 + compose（app+pgvector） | K8s/托管服务 + 镜像仓库 + CI 构建 | Todo5-5 CI/CD |
| 前端 | 单页 React，无状态管理库 | 组件库/状态管理/构建产物 CDN 化 | 按需 |
| 坑 | ① SSE 误用 `req.on("close")`——POST body 读完即触发，agentLoop 起步就移除 listener 丢日志 ② SPA 回退吞掉 API 404 ③ 启发式 `:id` 归并把 "sessions" 误判成动态段 ④ chat 走云 + embedding 走本地时 baseURL 必须分离（LM Studio 无云端 embedding 模型 → 404） | — | 全部已修复并实测 |
